<Section number="02" title="THE PROBLEM">

A construction project-controls SaaS had outgrown its React/Vite setup. The main dashboard was a single ~3,100-line component, large bill-of-quantities (BOQ) tables froze the browser, and data loaded through a chain of sequential queries.

</Section>

<Section number="03" title="WHAT I BUILT">
<Decisions>

<Decision n="01" title="Move the application boundary" diagram={"57 routes → App Router → SSR auth → middleware"}>

Migrated 57 routes to Next.js 14 App Router, with Supabase SSR authentication and middleware. The server owns access checks before a protected screen renders.

</Decision>

<Decision n="02" title="Make the dashboard understandable" diagram={"views → services → data access\n          ↘ export hooks"}>

Split the ~3,100-line dashboard into modular views, calculation services and export hooks. Enforced the API/data-access boundary with strict TypeScript and ESLint.

</Decision>

<Decision n="03" title="Keep heavy work off the interface" diagram={"visible rows → virtual window\nexports → worker → download"}>

Virtualized BOQ tables with TanStack React Virtual. Moved Excel and PDF processing into Web Workers so exports no longer compete with interface work on the main thread.

</Decision>

<Decision n="04" title="Retrieve data together" diagram={"sequential requests → server retrieval → 1 round trip"}>

Replaced an O(N) Supabase query waterfall with consolidated server-side retrieval. The client requests the result in one round trip.

</Decision>

<Decision n="05" title="Put limits around AI" diagram={"request → account limit → generation → validation"}>

Added grounded validation of AI-generated narratives and database-backed usage limits. Validation and account limits sit alongside the feature rather than relying on the prompt alone.

</Decision>

</Decisions>
</Section>

<Section number="06" title="WHAT I’D DO NEXT">

I would add repeatable performance budgets around the largest BOQ datasets and export paths, and trace server retrieval separately from rendering. That would make regressions visible before users encounter them, and provide measured timings for the next iteration.
