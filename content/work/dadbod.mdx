<Section number="02" title="THE PROBLEM">

A diet-planning application needed to turn calorie calculations into a clear daily plan on a tight deadline. Users needed a responsive experience for TDEE calculations and carb- or keto-cycling plans.

</Section>

<Section number="03" title="WHAT I BUILT">
<Decisions>

<Decision n="01" title="Make the calculation flow explicit">

Built TDEE calculation and carb/keto-cycling logic into the planning experience. Users move from their inputs to a calorie and diet plan.

```text
user inputs → TDEE → calorie target → diet plan
```

</Decision>

<Decision n="02" title="Keep state predictable">

Built the interface with React and Redux, keeping the plan and the user's inputs coordinated across the application.

```text
inputs → Redux state → calculations → views
```

</Decision>

<Decision n="03" title="Ship for small screens">

Delivered a fully responsive application within a tight deadline. The product reached about 1,000 monthly users internationally within its first year.

```text
mobile ↔ tablet ↔ desktop
```

</Decision>

</Decisions>
</Section>

<Section number="06" title="WHAT I’D DO NEXT">

I would separate the calculation rules into a well-tested domain module and improve the explanation of how each target is derived. Clear assumptions matter in a planning tool: the user should be able to understand the result and adjust their inputs.
